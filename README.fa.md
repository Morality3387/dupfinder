# 🔁 DupFinder — رباتِ پیدا کردنِ فیلم‌های تکراریِ کانال

> رباتِ تلگرامی که **کلِ فیلم‌های کانال‌های شما** را می‌بیند، آن‌ها را با سه اولویت
> (**نامِ فایل ← کپشن ← حجم+زمان**) مقایسه می‌کند، با **هشِ محتوا** تأییدِ قطعی می‌گیرد و
> نتیجه را **فوروارد** می‌کند تا با یک کلیک روی همان پستِ کانال برگردید.
>
> 🛡 **این ربات هیچ فایلی را پاک یا ویرایش نمی‌کند.** فقط می‌خواند، مقایسه می‌کند و فوروارد می‌کند.

## ۱) در یک نگاه

| کار | شرح |
|---|---|
| 📡 **کانال‌ها** | چند کانال را اضافه می‌کنید (ربات باید در کانال **ادمین** باشد) |
| 🔍 **اسکنِ کامل** | کلِ تاریخچهٔ کانال خوانده می‌شود — نه فقط پست‌های تازه |
| 📊 **نوارِ درصد** | درصد، پیام‌های بررسی‌شده و تعدادِ فیلم‌های پیداشده، زنده به‌روز می‌شود |
| ⏹ **کنسل** | هر لحظه می‌توانید متوقف کنید؛ آنچه تا آن لحظه خوانده شده **حفظ** می‌شود |
| 🧬 **هشِ محتوا** | سر + میانه + دُمِ فایل (هر تکه ۱۲۸KB) هش می‌شود — نه دانلودِ کاملِ فایل |
| 📎 **فوروارد** | فایل‌های هر گروه به چتِ خودتان فوروارد می‌شود ⇒ با یک کلیک روی پستِ اصلی |
| 📤 **فورواردِ همه با یک دکمه** | همهٔ تکراری‌های اسکن پشتِ‌سرهم می‌آید (با سرتیترِ هر گروه و «اصلی/تکراری») ⇒ بررسیِ سریع و پاک‌کردنِ دستیِ خودتان |
| 📷 **ورود با QR** | بدونِ فرستادنِ کدِ ورود در چت (پیشنهادی برای رفعِ ارورِ «code previously shared») |
| ➕ **ادمین‌کردنِ ربات با یک دکمه** | ربات خودش را ادمینِ کانال می‌کند — **بدونِ** مجوزِ حذفِ پیام |
| 🛡 **بی‌خطر** | ربات هیچ‌چیز را پاک/ویرایش نمی‌کند؛ فقط شما تصمیم می‌گیرید |
| 💾 **حافظهٔ اسکن** | نتیجه در SQLite (روی والیومِ Railway) می‌ماند؛ اسکنِ بعدی فقط تازه‌ها را می‌خواند |

**جریانِ کار در ۳ حرکت:** کانال را اضافه کن → «🔍 اسکن کامل» → «🔁 دیدنِ گروه‌ها» و فوروارد.

## ۲) سه سطحِ تشخیص (معنیِ ستاره‌ها)

| ستاره | نامِ فیلتر | وقتی می‌دهیم که… | اعتبار |
|---|---|---|---|
| ★★★★ | **قطعی** | هشِ محتوای فایل‌ها **یکسان** است (سر+میان+دُم بایت‌به‌بایت) یا شناسهٔ فایلِ تلگرام یکی است | قطعی (تقریباً ۱۰۰٪) |
| ★★★ | **حجم+زمان** | حجم و زمانِ ویدیو یکسان است (مثلاً هر دو **۵۰ مگابایت و ۱ دقیقه**) | احتمالِ بالا |
| ★★ | **نامِ مشابه** | نامِ فایل پس از نرمال‌سازیِ فارسی/عربی مشابه است (مثل `Inception 1080p` و `Inception 720p`) | متوسط |
| ★ | **کپشن** | فقط متنِ کپشنِ پست یکسان است | ضعیف — برای بازبینیِ دستی |

> دکمه‌های فیلتر (★★★★ / حجم+زمان / نام / کپشن / فقط رسیدگی‌نشده) **هم‌پوشانی** دارند:
> یک گروه می‌تواند هم هشِ یکسان داشته باشد و هم نامِ مشابه، پس در چند فیلتر دیده می‌شود.
> **تمرکزِ اصلی روی ★★★ (حجم + زمان) است**؛ همان موردی که خواستید.

هر گروه **دلیلِ تشخیص** خودش را نشان می‌دهد، مثلاً:
`دلیل: هشِ محتوا یکسان + نام مشابه + کپشن مشابه + حجم و زمان یکسان`.

## ۳) سه چیزی که این ربات نمی‌کند

1. ❌ **فایل پاک نمی‌کند.** هیچ‌جا `deleteMessage` روی محتوای کانال صدا زده نمی‌شود.
   تنها حذفِ موجود در کد، پاک‌کردنِ **پیامِ خودِ ربات در چتِ خصوصیِ شما** است
   (پیامِ کدِ ورود و رمزِ دو‌مرحله‌ای، برای امنیتِ خودتان).
2. ❌ **ویرایش نمی‌کند.** هیچ پست یا کپشنی در کانال دست‌کاری نمی‌شود.
3. ❌ **فایل‌ها را دانلود نمی‌کند.** فقط سر/میانه/دُمِ هر فایل (۳×۱۲۸KB) خوانده می‌شود
   تا هش ساخته شود؛ یعنی برای ۱۰۰۰ فیلمِ ۵۰۰ مگابایتی هم پهنای‌باند ناچیز است.

## ۴) راه‌اندازی روی Railway (گام‌به‌گام)

### گام ۱ — ساختِ ربات و گرفتنِ توکن
1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام بدهید.
2. `/newbot` → نام و یوزرنیم (باید به `bot` تمام شود) → توکن می‌گیرید:
   `123456789:AA...`
3. (اختیاری، پیشنهاد می‌شود) `/setprivacy` → **Disable** اگر می‌خواهید در گروه‌ها هم همهٔ پیام‌ها را ببیند.

### گام ۲ — آیدیِ عددیِ خودتان
1. به [@userinfobot](https://t.me/userinfobot) پیام بدهید → عددِ `Id` را بردارید (مثلاً `123456789`).
2. یا ربات را یک‌بار اجرا کنید، `/id` بزنید و عددِ `user_id` را ببینید.
   اگر `OWNER_ID` خالی بماند، ربات **خودسرانه مالک نمی‌گیرد**: یک کدِ یک‌بارمصرف در
   **لاگِ سرور** (Railway → سرویس → Logs) چاپ می‌شود و باید آن را در چتِ ربات بفرستید:
   `/claim 123456`. می‌توانید کدِ ثابت را در متغیر `OWNER_CLAIM_CODE` بگذارید
   (یا مستقیم `OWNER_ID` را پر کنید).

### گام ۳ — گذاشتنِ کد روی GitHub
```bash
git init
git add .
git commit -m "DupFinder 1.0.0"
git branch -M main
git remote add origin https://github.com/<user>/<repo>.git
git push -u origin main
```

### گام ۴ — ساختِ سرویس در Railway
1. [railway.app](https://railway.app) → **New Project** → **Deploy from GitHub repo** → همین ریپو.
2. Railway فایلِ `Dockerfile` را خودش تشخیص می‌دهد (`railway.json` هم آماده است).
3. **Variables** را پر کنید (حداقلِ لازم):

   | متغیر | مقدار | توضیح |
   |---|---|---|
   | `BOT_TOKEN` | `123456:AA...` | توکنِ BotFather — **لازم** |
   | `OWNER_ID` | `123456789` | آیدیِ خودتان (اختیاری ولی توصیه‌شده) |
   | `DB_PATH` | `/data/dup.db` | دیتابیس روی والیوم |
   | `TG_API_ID` / `TG_API_HASH` | از my.telegram.org | برای تاریخچهٔ کامل (گامِ ۵) |

4. **Volume** بسازید و به مسیرِ `/data` وصل کنید (Settings → Volumes → Mount path: `/data`).
   بدونِ والیوم، با هر دیپلوی دیتابیسِ اسکن‌ها از صفر شروع می‌شود.
5. Deploy. در تبِ **Logs** باید ببینید:
   `ربات آماده است (@YourBot)` و `سرویسِ سلامت روی پورت …`.
6. سرویسِ سلامت: `GET /` و `GET /health` پاسخِ JSON می‌دهند (برای healthcheckِ Railway).

### گام ۵ — (اختیاری ولی برای «کلِ تاریخچه» لازم) حسابِ کاربری
در ربات: «🔑 اتصالِ حسابِ کاربری» → `api_id` → `api_hash` → شمارهٔ تلفن → کدِ تلگرام → (رمزِ دو‌مرحله‌ای).
جزئیات در بخشِ بعد.

### ⚠️ نکاتِ مهمِ Railway (همین‌ها باعثِ «کرش» می‌شوند)

| مشکل | پیامِ Railway | راهِ حل |
|---|---|---|
| دستورِ `VOLUME` در داکرفایل | `dockerfile invalid: docker VOLUME at Line 20 is not supported, use Railway Volumes` | این خط در نسخهٔ فعلی **حذف شده**؛ والیوم را از داشبورد بسازید (Settings → Volumes → Mount path = `/data`) |
| دیپلوی از **فورکِ قدیمی** | همان خطای بالا مدام تکرار می‌شود | در GitHub → فورکِ خودتان → **Sync fork → Update branch** (تا کامیتِ اصلاح‌شده بیاید) و سپس Deploy |
| `railway.json` (Config as Code) | `Config as Code (railway.json / railway.toml) is deprecated` | فقط هشدار است (تا ۱ دسامبر ۲۰۲۶ کار می‌کند)؛ دست‌نخورده بگذارید |
| «کرش» بعد از استارت | `BOT_TOKEN تنظیم نشده` یا `توکنِ ربات نامعتبر است` | Variables را چک کنید؛ کدِ خروج ۲ یا ۳ در Logs |
| بعد از هر دیپلوی، اسکن‌ها پاک می‌شوند | — | والیوم روی `/data` را وصل کنید |

> 🔎 **کجای Logs را ببینیم؟** Railway → سرویس → **Deployments** → روی دیپلوی بزنید →
> تبِ **Build Logs** (خطاهای ساخت) و **Deploy Logs** (خطاهای اجرا). خطِ
> `dockerfile invalid …` یک خطای **Build** است، نه اجرا؛ یعنی کدِ ربات هیچ‌وقت اجرا نشده.
> لاگِ موفقِ ربات با این خط شروع می‌شود: `ربات آماده است (@YourBot)`.

### گام ۶ — افزودنِ کانال و اسکن
ربات را در کانال **ادمین** کنید (حتماً با اجازهٔ فوروارد/خواندن) → «➕ افزودنِ کانال» → یوزرنیم یا فورواردِ یک پست →
«🔍 اسکن کامل».

## ۵) 🔑 حسابِ کاربری: چرا لازم است و چطور وصل می‌شود

### چرا؟
ربات‌های معمولی (**Bot API**) به دو دلیل **کلِ تاریخچهٔ کانال** را نمی‌بینند:
- در **کانال‌ها**، ربات فقط پست‌هایی را می‌بیند که **بعد از ادمین‌شدنش** منتشر شده‌اند؛
  پست‌های قبلی (حتی اگر ربات ادمین باشد) از دیدِ Bot API پنهان‌اند.
- در **گروه‌ها**، فقط پیام‌های بعد از اضافه‌شدنِ ربات را می‌بیند.

برای دیدنِ **از اولین پست تا آخرین پست** باید یک **حسابِ کاربری** (MTProto/Telethon) وصل شود؛
حسابِ کاربری `messages.getHistory` کامل دارد و دانلودِ جزئی هم می‌تواند انجام دهد.

### چطور `api_id` / `api_hash` بگیریم؟
1. به [my.telegram.org](https://my.telegram.org) بروید → با شمارهٔ خودتان وارد شوید.
2. **API development tools** → یک اپ بسازید (نامش دلخواه).
3. `api_id` (عدد) و `api_hash` (رشتهٔ ۳۲ حرفی) را بردارید.

> ⚠️ **توصیهٔ امنیتی:** بهترین کار این است که برای این ربات یک **حسابِ تلگرامِ مخصوصِ کار**
> بسازید و آن را در کانال‌ها ادمین کنید. سشنِ یک حساب = دسترسیِ کامل به آن حساب.
> حسابِ اصلیِ خودتان را فقط اگر مایلید وصل کنید.

### روش‌های اتصال
- **از داخلِ ربات (ساده‌تر):** «🔑 اتصالِ حسابِ کاربری» →
  ۱) اگر `api_id`/`api_hash` را در Variables گذاشته باشید، **این گام‌ها پرسیده نمی‌شود** و مستقیم می‌رود سرِ شماره؛
  در غیر این صورت اول همان دو مقدار پرسیده می‌شود.
  ۲) دکمهٔ **«📱 ارسالِ شمارهٔ من»** را بزنید (شماره خودش می‌رود؛ لازم نیست تایپ کنید) —
  یا شماره را با کدِ کشور بنویسید: `+31…`.
  ۳) کدِ ۵ رقمیِ تلگرام را **رقم‌رقم** بفرستید: `1 2 3 4 5` — ⛔️ **هرگز به‌هم‌چسبیده (`12345`) نفرستید!**
  ۴) اگر حسابتان **رمزِ دو مرحله‌ای** دارد، قدمِ بعد رمز را می‌پرسد (۳ تلاش؛ بعد از آن برای امنیت لغو می‌شود).
  پیام‌های کد/رمز **بی‌درنگ از چت پاک می‌شوند**.

> 🛡 **مهم‌ترین نکتهٔ ورود (تجربهٔ واقعی):** تلگرام پیام‌هایی که **کدِ ورودِ یک‌پارچه** در آن‌ها باشد را
> «قبلاً به‌اشتراک‌گذاشته» می‌شمارد و ورود را **بلاک** می‌کند؛ در تلگرام پیامِ
> «⚠️ *Incomplete login attempt … the code was entered correctly, but sign in was not allowed,
> because this code was previously shared by your account*» می‌آید و به ربات فقط خطای گمراه‌کنندهٔ
> `The confirmation code has expired` برمی‌گردد. **پس:**
> - ✅ کد را **رقم‌رقم** بفرستید: `1 2 3 4 5` (یا `1.2.3.4.5` یا `1-2-3-4-5`)
> - ⛔️ هرگز `12345` چسبیده نفرستید — ربات هم آن را **قبول نمی‌کند** و `sign_in` را صدا نمی‌زند
>   تا کد و حسابِ شما بلاک نشود.
> - کدِ سوخته دیگر کار نمی‌کند ⇒ اول **«🔁 ارسالِ کدِ تازه»**، بعد کدِ جدید را رقم‌رقم بفرستید.

> ⏱ **«کد منقضی شد» یک علتِ دیگر هم دارد:** هر بار کدِ تازه بگیرید، **کدِ پیامِ قبلی باطل می‌شود**.
> ربات در همهٔ این حالت‌ها از شما شروعِ مجدد نمی‌خواهد: پیامِ روشن + دکمهٔ **«🔁 ارسالِ کدِ تازه»**.
- **با متغیرِ محیطی:** `TG_API_ID`, `TG_API_HASH`, `TG_SESSION_STRING`.
- **📷 ورود با QR (بدونِ کد و بدونِ ریسک):** در «🔑 اتصالِ حسابِ کاربری» → «📷 ورود با QR» → روی لینکِ
  `tg://login?…` بزنید و در تلگرام «تأیید» کنید. کدِ ورودی در هیچ پیامی فرستاده نمی‌شود، پس
  مشکلِ «code previously shared» پیش نمی‌آید. لینک خودش هر ۳۰ ثانیه تازه می‌شود.
- **با دستورِ سشن:** `/setsession <session_string>` (رشتهٔ سشنِ ازپیش‌ساخته).
- **اصلاحِ کلیدهای ذخیره‌شده:** اگر `api_id`/`api_hash` غلط ذخیره شده باشد، در «🔑 اتصالِ حسابِ کاربری»
  دکمهٔ **«🔧 تغییرِ api_id/api_hash»** آن‌ها را پاک می‌کند تا از Variables یا ورودیِ تازه استفاده شود.

سشن در دیتابیس ذخیره می‌شود؛ با هر بار بالا آمدنِ سرویس خودکار وصل می‌شود
(در منوی اصلی: «🔑 حسابِ کاربری … ✅ وصل»).

### اگر حسابِ کاربری وصل نکنید چه می‌شود؟
- اسکن کار می‌کند، ولی **فقط برای پست‌های بعد از ادمین‌شدنِ ربات**؛
- در گامِ اسکن، ربات به‌جای اسکنِ محدود، پیامِ «🔑 اتصالِ حساب» / «⚠️ اسکنِ محدود» را نشان می‌دهد
  (حالتِ محدود در نسخهٔ ۱.۰ پیاده نشده و عمداً مسدود است تا نتیجهٔ ناقص به شما داده نشود).
- **راهِ جایگزینِ بدونِ حساب:** پست‌های قدیمیِ کانال را در یک کانالِ آرشیو فوروارد کنید
  و همان کانالِ آرشیو را اسکن کنید.

## ۶) راهنمای استفاده از ربات (دکمه‌به‌دکمه)

### 🏠 منوی اصلی
`/start` → وضعیتِ کانال‌ها، فایل‌ها، تعدادِ گروه‌های تکراری و وضعیتِ حسابِ کاربری.
اگر اسکنی در جریان باشد، دکمهٔ «⏹ توقف و کنسل» بالای منو ظاهر می‌شود.

### ➕ افزودنِ کانال (سه روش)
1. **یوزرنیم:** `@myChannel`
2. **لینک:** `https://t.me/myChannel` (لینک‌های دعوتِ خصوصیِ `t.me/+AbCdEf` پشتیبانی **نمی‌شوند**)
3. **فورواردِ یک پست:** یک پست از کانال را برای ربات فوروارد کنید (بدونِ متن یا با `/`).

روشِ ۴ (حسابِ کاربری): شناسهٔ عددی مثل `-1001234567890`.

### 🔍 اسکن
روی نامِ کانال بزنید → **«🔍 اسکن کامل (تاریخچهٔ کامل)»**.
- **نوارِ درصد** + «پیام‌های بررسی‌شده» + «ویدیوهای پیداشده» زنده به‌روز می‌شود.
- فازها: `📥 مرورِ تاریخچه` → `🧬 هش‌گذاریِ نامزدها` → `🧠 تحلیل و گروه‌بندی` → `✅ پایان`.
- **⏹ توقف و کنسل:** در هر لحظه. فایل‌های خوانده‌شده حفظ می‌شوند و گروه‌بندیِ همان مقدار انجام می‌شود.
- **«🔄 ادامهٔ اسکن (فقط جدیدها)»:** فقط پیام‌های تازه‌تر از آخرین اسکن را می‌خواند
  (سریع؛ در گزارش با یادداشتِ «🔄 ادامهٔ اسکن» مشخص می‌شود). گروه‌بندی روی کلِ ایندکس انجام می‌شود.
- **`/scanall`** (یا دکمهٔ «🔍 اسکنِ همه»): همهٔ کانال‌ها را پشتِ‌سرهم و کامل اسکن می‌کند.

### ⚙️ تنظیمات (و اگر «کار نکرد»)
**هر گزینه توضیحِ خودش را دارد** — لازم نیست چیزی از قبل بدانید:
• 👈 در «⚙️ تنظیمات» روی هر دکمه بزنید ⇒ **توضیحِ فارسی** («این گزینه چیست») + **گزینه‌های ممکن با
نتیجهٔ هرکدام** + مقدارِ فعلی و پیش‌فرض + یک نکتهٔ کاربردی می‌آید.
• برای تغییر، **دکمهٔ همان مقدار را بزنید** — همان لحظه ذخیره می‌شود و روی همان صفحه ✅ می‌خورد
(لازم نیست چیزی تایپ کنید). اگر مقدارِ دلخواه دارید: «✏️ تایپ می‌کنم».
• «❓ هر گزینه یعنی چه؟» (یا `/settings راهنما`) ⇒ راهنمای کاملِ **همهٔ** تنظیم‌ها پشتِ‌سرهم.
• منو **دسته‌بندی‌شده** است: 🔑 تشخیص و هش · 🎯 حساسیت (آستانه‌ها) · 📏 حجم و زمان · 🧩 گروه‌بندی ·
📥 اسکن و ایندکس · 📎 فوروارد.
• «♻️ پیش‌فرضِ همین گزینه» فقط همان یک مورد را برمی‌گرداند؛ «♻️ بازگشتِ همه به پیش‌فرض» همه را.
• مقدارهای بله/خیر به‌صورتِ **روشن/خاموش** نشان داده می‌شوند (نه `True/False` انگلیسی).
• سه راه: «🏠 منوی اصلی» ← **«⚙️ تنظیمات»** · دستورِ `/settings` · تغییرِ متنی: `/set کلید مقدار`.
• **مقدارهای فارسی هم قبول است**: `کامل`=`full` · `نمونه`=`sample` · `همه`=`all` · `خاموش/روشن`=0/1 ·
`سخت‌گیرانه`=`strict` · `زنجیره‌ای`=`loose` — و **ارقامِ فارسی** («۰.۶») هم خوانده می‌شود.
• اگر مقدارِ نامعتبر بفرستید، **حالتِ انتظار باقی می‌ماند** و همان‌جا مقدارِ درست را بفرستید (قبلاً پاک می‌شد و
مقدارِ بعدی به دستِ تنظیمات نمی‌رسید — همان «تنظیمات کار نمی‌کند»).
• برچسبِ دکمه‌ها **کوتاه** است و توضیحِ کامل در متنِ پیام؛ اگر تلگرام کیبورد را رد کند، متن می‌رود و راهِ
`/set` گفته می‌شود (هیچ‌وقت بی‌صدا نمی‌ماند).
• نمونه‌ها: `/set hash_scope full` · `/set گروه‌بندی سخت‌گیرانه` · `/set th_cap_ratio 0.6` · `/set min_caption_len 8`.
• «♻️ بازگشت به پیش‌فرض» همه را به مقدارهای اولیه برمی‌گرداند. ورود به تنظیمات و `/set` **فقط برای مالک** است
(ادمین پیامِ روشن می‌گیرد: «فقط در دستِ مالکِ ربات است»).

### 🩺 چه دسترسی‌ای لازم است؟ (اکانت لازم نیست ادمین باشد)
| کاری که می‌خواهید | ربات در کانال | حسابِ کاربری |
|---|---|---|
| **اسکنِ کاملِ تاریخچه** | لازم **نیست** | باید **عضو** باشد — برای کانالِ **عمومی** حتی عضویت هم لازم نیست |
| **دیدنِ نامِ کانال** (خودکار) | اگر عضو/ادمین باشد خودکار؛ وگرنه با فورواردِ یک پست یا نامِ دستی | اگر عضو باشد خودکار |
| **دکمهٔ «➕ ادمین‌کردنِ ربات»** | باید ادمین باشد | باید ادمین باشد |
| **فورواردِ نتیجه به چتِ شما** | لازم نیست (اگر ربات نباشد با حسابِ کاربری فوروارد می‌شود) | عضو باشد کافی است |

پس خلاصه‌اش:
• **اکانتِ اصلی لازم نیست ادمینِ کانال باشد** — فقط کافی است **عضو** باشد (و برای کانالِ عمومی همین هم لازم نیست).
• **ربات هم لازم نیست ادمین باشد**؛ ولی اگر ربات عضو/ادمین نباشد، «نامِ خودکار از تلگرام» و
«ادمین‌کردنِ یک‌ضربه‌ای» کار نمی‌کند (نام را دستی یا با فوروارد می‌گذارید؛ فوروارد هم با حساب می‌رود).
• «فقط ربات را اضافه کنم و بدونِ حساب چک کند» **ممکن نیست**: Bot API هیچ متدی برای خواندنِ
تاریخچهٔ کانال ندارد و پست‌ها را هم فقط از لحظهٔ ادمین‌شدن می‌بیند. راه‌حل‌ها: ① حسابِ کاربری
(عضو) وصل کنید، ② یا پست‌های قدیمی را در یک **کانالِ آرشیو** فوروارد کنید و همان را اسکن کنیم،
③ یا برای کانالِ **عمومی** از «⚠️ اسکن محدود» (پیش‌نمایشِ t.me/s، بدونِ حجم/هش) استفاده کنید.
• دکمهٔ **«🩺 دسترسی‌های لازم»** در کارتِ هر کانال وضعیتِ واقعی (ربات/حساب) را نشان می‌دهد و
دقیقاً می‌گوید چه چیزی الان کار می‌کند.

### 📡 نامِ کانال (همیشه نام، هرگز شناسه)
• در فهرست و کارتِ کانال **نام** نشان داده می‌شود؛ اگر نام از تلگرام خوانده نشد، به‌جای شناسه
«کانالِ بینام» می‌آید و یک راهنما کنارَش نمایش داده می‌شود.
• سه راهِ رفعِ «بدون نام»: ① یک **پستِ همان کانال** را برای ربات فوروارد کنید (نام از خودِ پیام
خوانده و ذخیره می‌شود)، ② دکمهٔ **«✏️ نامِ کانال را دستی بگذار»**، ③ «🔄 تلاشِ دوباره برای
نامِ کانال‌ها» (نام‌ها را از تلگرام می‌گیرد؛ حداکثر ۵ تلاش در هر بار با کول‌داونِ ۱۰ دقیقه‌ای).
• افزودنِ دوبارهٔ یک کانال، **نامِ قبلیِ ذخیره‌شده را پاک نمی‌کند**.

### 👥 ادمین‌های ربات (چندنفره)
مالک می‌تواند چند نفر را ادمین کند تا با ربات کار کنند (اسکن، مشاهدهٔ نتیجه، فوروارد):
• منوی اصلی ← **«👥 ادمین‌های ربات»** ← **«➕ افزودنِ ادمین»** ⇒ شناسهٔ عددی طرف را بفرستید
(یا یک **پیامِ فورواردشده از او** بفرستید).
• دستورهای سریع (فقط مالک): `/addadmin 123456789` · `/deladmin 123456789` · `/admins`.
• اگر غریبه‌ای به ربات پیام بدهد، مالک یک اعلان با دکمهٔ **«➕ افزودن به‌عنوان ادمین»** می‌گیرد
(هر کاربر فقط **یک‌بار** معرفی می‌شود تا اسپم نشود).
• ادمین: اسکن، گزارش، فوروارد و **«⚙️ تنظیمات»** را دارد؛ فقط «🔑 حسابِ کاربری» (sessionِ تلگرامِ مالک)،
  «👥 مدیریتِ ادمین‌ها» و «🗑 حذفِ کانال از فهرست» در دستِ مالک است.
• شناسهٔ خودتان: در ربات دستورِ `/id` را بزنید.

### 📡 نامِ کانال به‌جای شناسه
فهرستِ کانال‌ها همیشه **نام** را نشان می‌دهد (نه شناسهٔ عددی). اگر نامی هنگامِ افزودن خوانده نشده باشد،
ربات با باز کردنِ فهرست خودش آن را از تلگرام می‌گیرد و ذخیره می‌کند؛ در غیرِ این‌صورت دکمهٔ
**«🔄 تلاشِ دوباره برای نامِ کانال‌ها»** را دارید و تا آن موقع «کانالِ بینام» نوشته می‌شود (هرگز شناسه).

### ♻️ اسکنِ ادامه‌ای و پست‌های ویرایش‌شده
هر بار «اسکن» می‌زنید، ربات به‌جای اینکه فقط از آخرین پیامِ دیده‌شده ادامه بدهد،
**`incr_tail` پیامِ آخر (پیش‌فرض ۲۰۰) را دوباره می‌خواند**. دلیل: اگر پستی را ویرایش کنید
و فایلش عوض شود، متادیتا و **هشِ کهنه** نباید بماند؛ ربات محتوای عوض‌شده را تشخیص می‌دهد،
هشِ قدیمی را باطل می‌کند و فایلِ تازه را از نو هش می‌کند (در گزارش هم می‌نویسد
«N فایل تغییر کرده بود»). ویرایشِ پیام‌های قدیمی‌تر از این پنجره فقط با **اسکنِ کامل** دیده می‌شود.

### 🧹 رکوردهای حذف‌شده و تغییرِ نوعِ فایل
• اگر پستی را در تلگرام **حذف** کنید، در «اسکنِ کامل» بعدی رکوردش از ایندکسِ ربات پاک می‌شود
(هیچ چیزی در تلگرام حذف نمی‌شود؛ فقط دیتابیسِ ربات تمیز می‌شود) و در گزارش هم می‌نویسد «🗑 N رکورد …».
• ملاکِ پاک‌سازی، **اتمامِ موفقِ اسکنِ کامل** است (نه «حداقل یک فایل پیدا شد»): اگر کانال را
کاملاً خالی کنید (همهٔ ویدیوها حذف شده‌اند) هم رکوردهای آن نوع پاک می‌شوند — فقط در حالتی که
هیچ پیامی پیمایش نشود، ربات از تلگرام تأییدِ «کانال خالی است» می‌گیرد وگرنه دست به ایندکس نمی‌زند.
• اگر نوعِ فایل‌های اسکن را عوض کنید (`video` ⇒ `all` مثلاً)، اسکنِ بعدی **خودکار کامل** می‌شود
تا فایل‌های قدیمیِ نوعِ تازه هم ایندکس شوند (وگرنه هرگز دیده نمی‌شدند).
• با عوض‌کردنِ `hash_scope` (مثلاً sample ⇒ full)، ربات فایل‌های قبلی را که دامنهٔ هششان
قدیمی است **از نو هش می‌کند** و در گزارش می‌نویسد «🔼 N فایل … از نو هش شد».

### 🔗 گروه‌های زنجیره‌ای و حالتِ سختگیرانه
گروه‌بندی گذراست: ممکن است `A` با `B` (نام) و `A` با `C` (کپشن) شبیه باشد ولی `B` با `C` نه.
در این حالت گروه با نشانهٔ «🔗 زنجیره‌ای» نشان داده می‌شود تا بدانید همهٔ اعضا به هم شبیه نیستند.
اگر می‌خواهید فقط گروه‌های کاملاً هم‌شبیه بمانید، `cluster_mode=strict` را بگذارید.

### 📊 گزارشِ اسکن
وضعیت، پیام‌های پیمایش‌شده، ویدیوهای دیده‌شده در این اسکن، کلِ ویدیوهای ایندکس‌شدهٔ کانال،
تعدادِ فایل‌های هش‌شده، و شمارشِ گروه‌ها به تفکیکِ ★★★★ / ★★★ / ★★ / ★.

### 🔁 گروه‌های تکراری
- **فیلترها:** همه · ★★★★ قطعی · ★★★ حجم+زمان · ★★ نام · ★ کپشن · فقط رسیدگی‌نشده.
- **صفحه‌بندی:** ۸ گروه در هر صفحه.
- روی هر گروه بزنید → **کارتِ گروه**:
  - فهرستِ فایل‌ها با نام، حجم، زمان، تاریخ (به وقتِ ایران) و کدِ پیام؛
  - دکمهٔ **«📎 فوروارد فایل‌های این گروه»** ⇒ **همهٔ** فایل‌های همان گروه، **تک‌به‌تک و بدونِ سقف**،
    به همین چت می‌آیند (در کانال‌های عمومی/خصوصی که ربات ادمین است، فوروارد ساخته می‌شود و با
    کلیک روی پیام، **همان پستِ کانال** باز می‌شود). یک بار می‌زنید و ربات **خودش تا آخر می‌رود** —
    دکمهٔ «ادامه» لازم نیست؛
  - دکمهٔ **«📤 همین گروه به گروهِ چک»** ⇒ فقط تکراری‌های همین گروه با سرتیتر به گروه/کانالِ شما؛
  - **«🔗 لینکِ پیام‌ها»** ⇒ لینکِ `https://t.me/...` هر پست (وقتی فوروارد ممکن نباشد)؛
  - **«✔ رسیدگی شد» / «🔒 نادیده بگیر»** ⇒ برای علامت‌زدن. وضعیت **کنارِ همان ردیف در فهرست** هم
    می‌آید: `✔ رسیدگی‌شده` · `🔒 نادیده` · `—` (بی‌تصمیم)؛ بعداً با فیلترِ «فقط رسیدگی‌نشده» فقط
    باقی‌مانده‌ها را می‌بینید.
  - اگر ربات اجازهٔ فورواردِ خودِ فایل را نداشته باشد، **صریح** می‌گوید: «فقط لینک رفت» + راهِ‌حل.

### 📤 فورواردِ همهٔ تکراری‌ها (بررسیِ سریع با یک دکمه)
در «📊 گزارشِ اسکن» یا «🔁 گروه‌های تکراری» دکمهٔ **«📤 فورواردِ همهٔ تکراری‌ها»** را بزنید:
- هر گروه با یک **سرتیتر** می‌آید: شمارهٔ گروه، ستاره‌ها، دلیلِ تشخیص، **🆕 اصلی‌ترین پست** و
  **تکراری‌ها** (بر اساسِ قدیمی‌ترین پست).
- بعد فایل‌های همان گروه فوروارد می‌شوند ⇒ با کلیک روی هر کدام، همان پستِ کانال باز می‌شود و
  خودتان تصمیم می‌گیرید کدام را پاک کنید. (ربات هیچ‌چیز را پاک نمی‌کند.)
- **سقفِ هر نوبت** ۴۰ فایل است؛ اگر بیشتر بود، دکمهٔ **«📤 ادامهٔ فوروارد»** می‌آید (جلوگیری از
  محدودیتِ تلگرام).
- گروه‌های **«🔒 نادیده بگیر»** رد می‌شوند و هر گروه فقط **یک‌بار** فرستاده می‌شود (دوباره اسپم نمی‌شود).
- فیلترِ جاری رعایت می‌شود: اگر روی «★★★ حجم+زمان» باشید، فقط همان‌ها فرستاده می‌شوند.
- <i>این دکمه نتیجه را به **همین چتِ ربات** می‌فرستد. اگر می‌خواهید به **گروهِ خودتان** برود، از «📤 گروهِ چک» استفاده کنید (پایین‌تر).</i>

### 📤 گروهِ چک — همهٔ تکراری‌ها کنارِ هم، در گروه/کانالِ خودتان
یک **مقصد** تعیین می‌کنید (گروه یا کانالِ خودتان) و بعد از هر اسکن، تکراری‌ها را یک‌جا همان‌جا
می‌فرستید تا **کنارِ هم** چک کنید:

| کار | چطور |
|---|---|
| تعیینِ مقصد — راهِ ۱ | یک **پیام از همان گروه/کانال** را برای ربات **فوروارد** کنید («📌 تعیینِ مقصد با فورواردِ یک پیام») |
| تعیینِ مقصد — راهِ ۲ | **تایپِ** `@username` یا `-100…` — «✏️ تعیین با یوزرنیم/شناسهٔ عددی» یا `⚙️ تنظیمات` ← «گروهِ چک» |
| تستِ دسترسی | «🧪 تستِ دسترسی به مقصد» ⇒ می‌گوید ربات می‌تواند در آن مقصد بنویسد یا نه |
| برداشتنِ مقصد | «🚫 برداشتنِ مقصد» یا فرستادنِ `خاموش` |
| فرستادنِ همه | دکمهٔ **«📤 همهٔ تکراری‌های اسکن را به گروهِ چک بفرست»** در گزارشِ اسکن/فهرست (یا `/check`) |
| فرستادنِ یک گروه | **«📤 همین گروه به گروهِ چک»** در کارتِ همان گروه |

قواعدِ کار (مطابقِ خواستهٔ کاربر):
- **هیچ‌وقت خودکار نمی‌فرستد** — فقط با دکمه. بعد از هر اسکن، خودتان تصمیم می‌گیرید.
- **سقفِ تعداد ندارد**: هر چه تکراری پیدا شده می‌رود (گروه‌های «🔒 نادیده» رد می‌شوند).
- هر گروه = یک **سرتیترِ خوانا** (شماره، ستاره‌ها، دلیل، 🆕 پستِ اصلی، ♻️ تکراری‌ها) و بعد
  فایل‌هایش **کنارِ هم** (پیش‌فرض: آلبوم — با تنظیمِ «تکراری‌ها کنارِ هم (آلبوم)» می‌شود تک‌به‌تک).
- زیرِ هر سرتیتر دکمهٔ **«🗑 این گروه را نفرست»** هست: اگر یک گروه اشتباه بود، همان‌جا ردش می‌کنید.
- دکمه‌های همیشه‌موجود: **📊 وضعیتِ ارسال** · **▶️ ادامهٔ ارسال** · **🔁 همه را از نو بفرست** ·
  **✔ همهٔ گروه‌ها رسیدگی‌شده** (تیک‌ها را یک‌جا در فهرست می‌گذارد).
- **پیش‌نیازِ مقصد:** ربات باید در آن گروه/کانال **عضو یا ادمین** باشد؛ اگر نباشد، هشدارِ روشن +
  راهِ‌حل (ادمین‌کردنِ ربات یا اتصالِ حسابِ کاربری) نشان داده می‌شود — **شکستِ خاموش نداریم**.
- مسیرِ ارسال مثلِ بقیهٔ ربات است: اول با **ربات**، بعد با **حسابِ کاربری**، بعد **کپی**، و در آخر
  اگر فایل قابلِ‌فوروارد نبود فقط **لینک**. در گزارش می‌بینید کدام مسیر رفته و چند مورد فقط «لینک» بوده.

### 🧹 اسکنِ تازه، نتیجهٔ اسکنِ قبلی را پاک می‌کند
با هر **اسکنِ کامل** (یا «🔄 ادامهٔ اسکن»/اسکنِ محدود)، نتیجهٔ اسکن‌های قبلیِ همان کانال از دیتابیسِ
ربات پاک می‌شود: گروه‌های تکراری، تیک‌های «رسیدگی»، وضعیتِ «قبلاً فرستاده شده» و صفِ گروهِ چک.
⇒ شمارنده‌ها و فهرست **از صفرِ همان اسکن** هستند، انگار از نو اسکن زده‌اید.
✔ **آرشیوِ فایل‌ها و هش‌ها می‌ماند** (اسکنِ تازه کند نمی‌شود و لازم نیست دوباره هش بگیرد) و
⚖️ در تلگرام **هیچ‌چیزی پاک/ویرایش نمی‌شود** — فقط دادهٔ خودِ ربات مرتب می‌شود.

### ➕ ادمین‌کردنِ ربات با یک دکمه
در کارتِ کانال: **«➕ ادمین‌کردنِ ربات در این کانال»**.
- این کار با **حسابِ کاربریِ وصل‌شده** انجام می‌شود (فقط ادمین‌ها می‌توانند ادمین اضافه کنند).
- 🛡 ربات فقط حقِ لازم را می‌گیرد و **هرگز** مجوزِ `delete_messages` نمی‌گیرد.
- اگر حسابِ شما ادمینِ کانال نباشد یا حریمِ خصوصی اجازه ندهد، پیامِ خطا + راهِ دستی نشان داده می‌شود.

### ⚙️ تنظیمات (بدونِ ری‌استارت)
«⚙️ تنظیمات» → پارامتر را انتخاب و مقدارِ تازه را بفرستید (ذخیره در دیتابیس، اعمالِ فوری).
`st:reset` همهٔ تنظیمات را به پیش‌فرضِ محیط برمی‌گرداند.

### ❓ راهنما
`/help` یا `/history` — همان متنی که در ربات می‌بینید، شاملِ توضیحِ محدودیتِ تاریخچه.

برای «دو فیلمِ ۵۰MB و ۱ دقیقه‌ای»: `size_tol_pct=0.5`، `size_tol_min=2048`، `dur_tol_s=2`

## ۹) چه چیزی «تکراری» شمرده می‌شود و چه چیزی نه

✅ **گرفته می‌شود**
- دو آپلودِ جدای **یک فایل** با نام‌های متفاوت (هشِ محتوا یکسان ⇒ ★★★★)
- همان فیلم با کیفیت‌های متفاوت (نامِ مشابه ⇒ ★★)
- **دو فایلِ هم‌حجم و هم‌زمان با نام و کپشنِ بی‌ربط** ⇒ ★★★ (موردِ اصلیِ درخواستِ شما)
- سه‌گانه‌ها و گروه‌های چندفایلی (هر تعداد فایل در یک گروه)

❌ **گرفته نمی‌شود (عمداً)**
- **قسمت‌های پشتِ‌سرهمِ یک سریال** (`S01E01` و `S01E02`): شمارهٔ قسمتِ متفاوت ⇒ تکراری نیست
  (حتی اگر حجمشان نزدیک باشد، چون شمارهٔ قسمت نرمال‌سازی و مقایسه می‌شود)
- **نام‌های کوتاهِ قالبی** مثل `video-3.mp4` و `video-30.mp4`: زیررشته‌ی هم نیستند (توکنِ عددیِ کامل مقایسه می‌شود)
- حجم/زمانِ فقط **نزدیک** (بدونِ یکیِ دقیق): با `size_time_require_one_exact=1` رد می‌شود
  (تا «همه‌چیز با همه‌چیز» مقایسه نشود)
- فایل‌های کوچک‌تر از `min_size_for_match` و ویدیوهای کوتاه‌تر از `min_duration_s`
- کپشن‌های عمومی و پرتکرار مثل «فیلم» تنها (کلماتِ بی‌ارزش حذف می‌شوند)

## ۱۰) محدودیت‌ها: چه چیزهایی پیدا نمی‌شود

| محدودیت | توضیح | راهِ حل |
|---|---|---|
| 🕰 **تاریخچهٔ قدیمی** | Bot API پست‌های قبل از ادمین‌شدن (و در کانال‌ها عملاً همه) را نمی‌بیند | 🔑 اتصالِ حسابِ کاربری ⇒ تاریخچهٔ کامل |
| 🚫 **کانال بدونِ ادمینیِ ربات** | بدونِ ادمین‌بودن در کانال، نه فوروارد ممکن است و نه دیدنِ پست‌ها | ربات را ادمین کنید |
| 🔒 **کانالِ `noforwards`** | فورواردِ خودِ تلگرام بلاک است | ربات خودکار سراغِ **لینکِ پیام** می‌رود؛ یا با حسابِ کاربری فوروارد می‌کند |
| 🗑 **فایلِ حذف‌شده** | چیزی که از کانال پاک شده در دسترسِ هیچ‌کس نیست | — (غیرِقابلِ بازیابی) |
| 🧬 **تفاوت در چند بایتِ میانی** | هشِ ما هشِ **جزئی** (سر+میانه+دُم) است، نه کلِ فایل | برای اطمینانِ نهایی، دو فایل را فوروارد کنید و خودتان مقایسه کنید |
| 🎞 **ویدیوهای درون‌فایل (مثل فایلِ zip)** | فقط ویدیو/سندِ ویدیویی اسکن می‌شود | `media_kinds=video+doc` یا `all` |
| 📉 **کانالی که ادمین دسترسیِ «پست‌های قبلی» نداده** | بعضی دسترسی‌های ادمینی محدود است | دسترسیِ «خواندنِ پیام‌ها» را بدهید |
| 🧮 **فایل‌های بزرگِ زیاد** | هر فایل ۳ تکه × ۱۲۸KB خوانده می‌شود؛ برای ۱۰۰۰ فایل ≈ ۳۸۰MB دانلودِ جزئی | `hash_mode=candidates` (پیش‌فرض) یا `off` |
| 🌐 **حذفِ حسابِ کاربری از طرفِ تلگرام** | سشنِ باطل‌شده | دوباره «🔑 اتصالِ حسابِ کاربری» |

## ۱۱) عیب‌یابی (خطاهای رایج و راهِ حل)

| نشانه / خطا | معنا | راه‌حل |
|---|---|---|
| `⚠️ BOT_TOKEN تنظیم نشده` | متغیرها خالی‌اند | `BOT_TOKEN` را در Railway Variables بگذارید |
| `dockerfile invalid: docker VOLUME … not supported` (Build Logs) | خطِ `VOLUME` در داکرفایلِ قدیمی | نسخهٔ جدید این خط را ندارد؛ اگر از فورک دیپلوی می‌کنید **Sync fork** بزنید |
| دیپلوی `FAILED` در چند ثانیه | خطای **Build** است نه اجرا | Build Logs را ببینید؛ معمولاً مشکلِ بالا |
| ربات جواب نمی‌دهد | سرویس کرش کرده | Logs را ببینید؛ `GET /health` را چک کنید |
| `⛔️ این ربات خصوصی است` | آیدیِ شما ≠ `OWNER_ID` | `OWNER_ID` را درست کنید |
| `⛔️ این ربات هنوز مالک ندارد` | `OWNER_ID` خالی است و کسی `/claim` نزده | کدِ لاگِ سرور را بفرستید: `/claim 123456` (یا `OWNER_CLAIM_CODE` بگذارید) |
| `⛔️ دسترسی ندارید — این ربات خصوصی است` | کاربر در فهرستِ ادمین‌ها نیست | مالک: `/addadmin <شناسهٔ عددی>` یا دکمهٔ اعلانِ «➕ افزودن به‌عنوان ادمین» |
| در فهرستِ کانال‌ها «کانالِ بینام» می‌بینم | نام از تلگرام خوانده نشد (ربات ادمین نیست/حسابِ کاربری وصل نیست) | «🔄 تلاشِ دوباره برای نامِ کانال‌ها» یا اتصالِ حسابِ کاربری، یا افزودنِ دوبارهٔ کانال با `@username` |
| `Bad Request: chat not found` | یوزرنیمِ اشتباه، یا ربات عضو نیست | یوزرنیمِ دقیق؛ ربات را ادمین کنید |
| `⚠️ لینکِ دعوتِ خصوصی … پشتیبانی نمی‌شود` | لینکِ `t.me/+AbCdEf` | با حسابِ کاربری شناسهٔ عددی (`-100…`) را بفرستید |
| `CHAT_ADMIN_REQUIRED` / فوروارد ناموفق | ربات در کانال ادمین نیست یا اجازهٔ فوروارد ندارد | ربات را ادمین کنید (اجازهٔ ویرایش لازم نیست) |
| `⏳ FLOOD_WAIT` در گزارشِ پیشرفت | تلگرام موقتاً محدود کرده | ربات خودش صبر و ادامه می‌دهد؛ `scan_wait_time` را بالا ببرید |
| `SESSION_REVOKED` / `سشن معتبر نیست` | سشن باطل شده | «🔑 اتصالِ حسابِ کاربری» را دوباره انجام دهید |
| `PHONE_CODE_INVALID` | کدِ اشتباه | همان کد را دوباره (با دقت) بفرستید یا «🔁 ارسالِ کدِ تازه» |
| `The confirmation code has expired` | یا کدِ **پیامِ قبلی** را زده‌اید، یا کد **قبلاً در یک پیام به‌اشتراک گذاشته شده** | «🔁 ارسالِ کدِ تازه» → **آخرین** کد را **رقم‌رقم** بفرستید |
| در تلگرام: «Incomplete login attempt … code was previously shared by your account» | کد **یک‌پارچه** در چت فرستاده شده (مثل `12345`) ⇒ تلگرام ورود را بلاک کرده | کدِ تازه بگیرید و **رقم‌رقم** بفرستید: `1 2 3 4 5` |
| ربات می‌گوید «این کد را قبول نکردم» | همان حالتِ بالا؛ ربات عمداً `sign_in` نمی‌زند تا حساب بلاک نشود | «🔁 ارسالِ کدِ تازه» → کدِ جدید رقم‌رقم |
| «این حساب رمزِ دو مرحله‌ای دارد» | بعد از کدِ درست، تلگرام رمزِ Two-Step می‌خواهد | همان رمزِ حساب را بفرستید (۳ تلاش) |
| شماره‌ام پیامِ «خودتان» می‌گیرد | با دکمهٔ تماس، مخاطبِ شخصِ دیگری را فرستاده‌اید | دکمهٔ «📱 ارسالِ شمارهٔ من» را برای **حسابِ خودتان** بزنید |
| «شماره باید با کدِ کشور باشد» | شمارهٔ محلی فرستاده‌اید (`0912…`) | با کدِ کشور بفرستید: `+98912…` (یا دکمهٔ «📱 ارسالِ شمارهٔ من») |
| نوارِ درصد روی ۰ می‌ماند | کانال خیلی کم پیام دارد یا Telethon اجازهٔ `count` نداده | صبر کنید؛ شمارشِ «پیام‌های بررسی‌شده» بالا می‌رود |
| «چیزی با این فیلتر پیدا نشد» | واقعاً تکراری پیدا نشد | فیلترِ «همه» را ببینید یا آستانه‌های نام/کپشن را کمی پایین بیاورید |
| اسکن روی ۰ ویدیو تمام شد | پست‌های قبل از ادمینی یا کپشن‌فقط | حسابِ کاربری را وصل کنید |
| «⚠️ اسکنِ محدود» | حسابِ کاربری وصل نیست | بخش ۵ را ببینید |
| دیتابیس بعد از دیپلوی خالی شد | والیوم وصل نیست | Volume روی `/data` بسازید |
| «⚠️ خطا در اسکن» | متنِ خطا در گزارش می‌آید | `LOG_LEVEL=DEBUG` و Logs را ببینید |

## ۱۲) امنیت و حریمِ خصوصی

- **توکن و سشن** فقط از متغیرهای محیطی/دیتابیس خوانده می‌شوند و **در چتِ تلگرام چاپ نمی‌شوند**؛
  در `Settings.as_public()` هم حذف می‌شوند. پیام‌های کد/رمزِ ورود **بی‌درنگ پاک** می‌شوند.
- **سرویسِ سلامت** هیچ دادهٔ حساسی برنمی‌گرداند (فقط شمارنده و وضعیت).
- **در دیتابیس چه ذخیره می‌شود؟** فراداده: نامِ فایل، حجم، زمان، ابعاد، کپشن، شناسهٔ پیام، تاریخ،
  و هشِ کوتاه. **هیچ ویدیویی دانلود و ذخیره نمی‌شود.**
- **دسترسی‌ها:** ربات فقط می‌خواند + فوروارد می‌کند. هیچ مجوزِ حذف/ویرایشی لازم ندارد؛
  اگر ترسیدید، در ادمین‌کردنِ ربات تیکِ «حذفِ پیام» را **نزنید** — ربات کار می‌کند.
- سشنِ حسابِ کاربری روی والیومِ `/data` است؛ اگر کسی به پنلِ Railway شما دسترسی دارد،
  عملاً به آن حساب دسترسی دارد ⇒ **حسابِ مخصوصِ کار** توصیه می‌شود.

## ۱۴) پرسش‌های پرتکرار

**۱) ربات فایل‌ها را پاک می‌کند؟** نه. هیچ‌جا روی محتوای کانال `deleteMessage` صدا زده نمی‌شود؛
تنها حذف، پاک‌کردنِ پیامِ خودِ ربات در چتِ خصوصیِ شماست (کد/رمزِ ورود).

**۲) برای اینکه کار کند باید ربات را کجا ادمین کنم؟** در همان کانال‌هایی که می‌خواهید اسکن شوند.
ادمین‌بودن برای **دیدنِ پست‌ها و فوروارد** لازم است. اگر فقط با حسابِ کاربری می‌خواهید کار کنید،
حسابِ کاربری باید عضو/ادمینِ کانال باشد.

**۳) اگر بخواهم فقط تکراری‌های «حجم و زمانِ یکسان» را ببینم؟** فیلترِ **★★★ حجم+زمان**.
این همان اولویتی است که رویش تأکید کردید (مثلِ دو فایلِ ۵۰ مگابایتیِ ۱ دقیقه‌ای).

**۴) چند کانال می‌شود اضافه کرد؟** محدودیتی در کد نیست؛ `/scanall` همه را پشتِ‌سرهم اسکن می‌کند.
هر اسکنِ کانال جداگانه ذخیره می‌شود.

**۴٫۵) فرقِ «🔍 اسکن مجدد» و «🔄 ادامهٔ اسکن»؟** اولی از صفر کلِ کانال را دوباره می‌خواند
(برای وقتی نام‌گذاری یا کپشن‌ها را در کانال عوض کرده‌اید)، دومی فقط پیام‌های تازه را می‌خواند.

**۴٫۸) چرا کد را باید رقم‌رقم بفرستم؟** چون تلگرام متنِ پیام‌ها را برای «اشتراک‌گذاریِ کدِ ورود» اسکن می‌کند؛ کدِ یک‌پارچه در چت ⇒ تلگرام ورود را بلاک می‌کند و به ربات خطای «expired» برمی‌گرداند. شکلِ رقم‌رقم (`1 2 3 4 5`) این تشخیص را رد می‌کند.

**۵) اسکن چقدر طول می‌کشد؟** برای هر ۱۰۰۰ پیام با `scan_wait_time=0.35` حدودِ ۶ دقیقه برای
مرورِ تاریخچه؛ هش‌گذاریِ نامزدها متناسب با تعدادِ نامزدها (هر فایل ۳ درخواستِ کوچک).
با «🔄 ادامهٔ اسکن (فقط جدیدها)» اسکن‌های بعدی ثانیه‌ای‌اند.

**۶) اگر بینِ دو کانال، فایلِ تکراری باشد چه؟** گروه‌بندی و هش **در سطحِ کانال** انجام می‌شود
(هر اسکن متعلق به یک کانال است)؛ برای مقایسهٔ دو کانال، هر دو را در یک کانالِ آرشیو جمع کنید
یا از `/scanall` برای دیدنِ وضعیتِ هر کدام استفاده کنید.

**۷) میتوانم مطمئن شوم نتیجه درست است؟** بله: هر گروه «دلیلِ تشخیص» را می‌گوید و ستاره‌ها
اعتبار را نشان می‌دهند. فایل‌های ★★★★ را فوروارد کنید و خودتان نگاه کنید؛ ربات چیزی را
خودسرانه پاک نمی‌کند.

**۸) دیتابیس را از صفر کنم؟** فایلِ `/data/dup.db` را پاک کنید (یا سرویس را بدونِ والیوم دیپلوی کنید)
⇒ اسکنِ بعدی همه‌چیز را از نو ایندکس می‌کند.

**۴٫۹) آیا یک گروه می‌تواند بیشتر از ۲ فایل داشته باشد؟** بله، بی‌نهایت محدودیت ندارد؛
گروه‌بندی با اتصالِ جفت‌ها ساخته می‌شود، پس اگر یک فیلم ۴ بار آپلود شده باشد **یک گروهِ ۴ فایلی** می‌بینید
(تستِ خودکار دارد: گروهِ ۳ و ۴ و ۵ و ۶ فایلی). اگر در کانالِ شما همهٔ گروه‌ها ۲ فایلی‌اند، یعنی
واقعاً هر فایل دو نسخه دارد.

**۴٫۱۰) چرا جای شناسهٔ عددی، نامِ کانال می‌بینم؟** چون خواستید 😊 همه‌جا (فهرستِ کانال‌ها، کارتِ
کانال، سرتیترِ گزارش‌ها) **نام/یوزرنیمِ کانال** نشان داده می‌شود، نه شناسهٔ عددی.

**۹) اگر کانال را از فهرست حذف کنم، فایل‌ها هم پاک می‌شوند؟** فقط از **دیتابیسِ ربات** حذف می‌شوند؛
در تلگرام هیچ اتفاقی نمی‌افتد و پیامِ تأیید هم همین را می‌گوید.
